# moa

흩어진 생각을 모아, 하나의 기록으로.

메모는 기기의 SQLite에 저장됩니다. AI 기능은 앱이 아니라 로컬 프록시 서버가 처리하며, AI API 키는 서버 환경 변수에만 둡니다.

## 실행

```bash
npm install
npm start
```

Android는 `npm run android`, iOS는 `npm run ios`, 웹은 `npm run web`입니다.

AI 프록시는 FastAPI입니다. Python 3.11 이상이 필요합니다.

```bash
py -m venv server\.venv
server\.venv\Scripts\python -m pip install -r server\requirements.txt
copy server\.env.example server\.env
npm run server
```

`server/.env`의 `OPENAI_API_KEY`에 키를 넣습니다. 키 파일은 git에 포함하지 않습니다. 키가 없어도 메모 작성, 저장, 검색, 휴지통은 동작하고, AI 기능만 설정이 필요하다는 안내를 보여 줍니다. 경로와 응답 형식은 이전과 같습니다. `/docs`에서 요청 형식을 볼 수 있습니다.

앱의 설정 화면에서 서버 주소를 바꿉니다. 기본값은 `http://127.0.0.1:8787`이고, `EXPO_PUBLIC_AI_PROXY_URL`로 기본 주소만 덮어쓸 수 있습니다. 이 값은 비밀이 아닙니다.

- Android 에뮬레이터: `http://10.0.2.2:8787`
- 같은 Wi-Fi의 실기기: 개발 PC의 LAN 주소
- 서버를 외부에 공개할 때는 `PROXY_AUTH_TOKEN`을 켜고, 앱 설정의 접근 토큰에 같은 값을 입력합니다. HTTPS를 쓰고 나면 Android cleartext는 끄는 편이 안전합니다.

AI를 처음 켜면, 메모 내용이 서버를 거쳐 외부 AI로 전달된다는 동의를 받습니다. 동의 전에는 자동 분석도 하지 않습니다.

## 앱에서 되는 일

- Markdown 편집과 미리보기, 자동 저장
- 사진 삽입. 본문에는 `attachment:{id}` 참조만 두고 파일은 앱 문서 폴더에 둡니다.
- 검색, 태그, 즐겨찾기, 고정, 최신순 정렬, 휴지통과 복원
- 생각 정리하기: 결과를 원본과 비교한 뒤 적용하거나 취소
- 저장 후 잠시 입력이 없으면 태그와 한 줄 요약 생성. 같은 내용은 다시 분석하지 않습니다.
- 비슷한 메모 추천과 직접 연결. 연결은 양쪽에서 보이고, 같은 쌍은 한 번만 저장됩니다.
- 메모를 여러 개 선택한 뒤 함께 모아보기. 결과는 새 메모이고 원본은 그대로입니다.
- AI로 메모 쓰기. 단어만 적어도 관련 메모로 풀어 주고, 작성 요청을 적어도 그 형식대로 본문을 만듭니다. 결과는 확인한 뒤 새 메모로 저장하거나 현재 메모에 넣습니다.

## 기술 선택

- Expo SDK 57, Expo Router, Zustand를 유지했습니다. 이미 있는 화면 구조와 테마를 바꾸지 않기 위해서입니다.
- 메모 저장은 AsyncStorage 대신 `expo-sqlite`입니다. 대량 메모를 키-값 저장소에 두지 않고, 태그·연결·첨부·통합 출처를 테이블로 나눴습니다. 예전 AsyncStorage 메모는 첫 실행 때 한 번만 가져옵니다.
- 설정처럼 작은 값은 AsyncStorage에 남겼습니다.
- Markdown은 편집 툴바와 미리보기를 분리했습니다. 나중에 다른 편집기로 바꿔도 저장 형식은 Markdown 문자열입니다.
- AI 호출은 `AIService`에 해당하는 `services/aiClient.ts`만 프록시로 보냅니다. 관련 메모 판단에는 전체 본문 대신 제목, 요약, 태그만 보냅니다. 모아보기는 선택한 메모의 본문을 보냅니다.
- 후보 검색은 `tagCandidateRetriever`로 분리해 두었습니다. 태그가 비슷하다고 무조건 연결하지 않으며, 이후 의미 검색을 같은 인터페이스에 추가할 수 있습니다.

## 확인한 것

앱 단위 테스트는 `npm test`, 프록시 테스트는 `npm run test:server`입니다. 키 없는 프록시의 `/v1/health`는 AI가 아직 설정되지 않았다고 응답하고, 키가 없으면 `/v1/organize`는 503입니다.

단위 테스트로 확인한 동작:

- 공백뿐인 수정은 같은 내용으로 보아 재분석을 건너뜀
- 사용자 태그는 AI가 다시 분석해도 유지되고, 지나치게 일반적인 태그는 버림
- 관련 메모 후보에서 자기 자신과 삭제된 메모를 제외
- 같은 메모 연결은 중복 생성되지 않음
- 모아보기는 새 메모를 만들고 원본 배열을 바꾸지 않음
- 관련 메모 요청 본문에 Markdown 원문이 들어가지 않음
- 프록시가 API 키를 응답에 포함하지 않음

## 아직 기기에서 확인하지 못한 것

이 환경에서는 iOS/Android 앱을 설치해 재실행하지 못했습니다. 그래서 아래는 코드와 단위 테스트로만 맞춰 두었고, 기기에서 성공했다고 보지 않습니다.

- 앱을 끄고 다시 열었을 때 SQLite 메모와 사진이 남아 있는지
- 자동 저장과 Markdown 미리보기의 실제 터치 흐름
- 사진 보관함 권한과 재실행 후 이미지 표시
- 실제 AI 키로 정리, 태그, 모아보기가 이어지는지
- 웹에서 SQLite와 파일 복사가 네이티브와 같게 동작하는지

웹에서는 사진 파일이 브라우저를 벗어나 안정적으로 남지 않을 수 있습니다. 사진이 있는 메모는 iOS와 Android에서 쓰는 것을 기준으로 했습니다.
